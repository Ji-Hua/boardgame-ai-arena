## 背景与问题

Quoridor 多次拆分与整合后，GitHub main、最新功能分支、服务器 checkout 和运行镜像已分离。用户难以判断当前主线，旧目录仍包含未提交源码、数据或现行服务依赖。

2026-11-22 核查：main 为 91788fd（4 月 19 日）；最新候选 codex/multi-game-rl-platform 为 93323ca（11 月 3 日），领先 main 143 个提交。dev 候选工作区干净。training 统一平台分支为 772e88f；实际运行组件来自 P5～P8。training 的原始 checkout 为 9737338，有 22 条状态记录，仍提供 Jobs 的 Git 仓库、Python 环境及 MLflow 配置。

## 目标

将有效的最新代码整合进 main，使 dev 与 training 使用一致、可追溯、可正常运行的主线版本；退出历史工作副本和旧服务，今后从 main 分叉开发并合回 main。

## 范围

- 核对本项目相关 GitHub 分支、双机仓库/worktree、独有提交和未提交修改。
- 保留最新候选已有的 Quoridor 和适用于 Quoridor 的共享研究平台能力；排除 Mr. Jack 专用代码、界面、依赖、测试和文档，历史分支及数据归档保全，解决整合与部署所必需的兼容问题。
- 主线合并、双机同步、运行依赖迁移、协调部署、实际验收及回滚保障。
- 历史源码归档至各主机 ~/archive/，旧服务及自动启动配置退役。
- 保存模型、实验、MLflow、任务与对局数据及其来源关系。
- 更新真实有效的开发、发布与恢复说明。

## 非目标

- 不重新设计系统，不新增游戏、训练算法或追求新的棋力指标。
- 不清理其他项目，不永久删除历史源码、模型或实验记录。
- 不因整合而提升 champion、变更模型晋升决定或重新训练全部历史模型。
- 已授权按计划执行合并、部署、迁移及旧服务退役；不删除历史数据。

## 约束与假设

- 用户明确跳过 Design；复用已有功能和双机职责，Plan 不引入新的产品行为契约。
- “只有主分支”解释为最终正式源码工作区只使用 main；开发时允许临时功能分支，归档保留历史 Git，发布快照和任务源码快照属于可追溯产物而非独立开发副本。
- 不强推、不重写共享历史、不覆盖未提交内容；模型和数据库不进入 Git。
- 93323ca 是当前候选起点，不预先断言其已包含全部独有工作。
- “正确运行”需要实际行为验收；HTTP 健康、历史测试数量或 GPU 空闲不能代替。
